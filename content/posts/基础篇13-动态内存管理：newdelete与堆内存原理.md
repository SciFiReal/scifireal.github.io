C++程序运行时的两大内存空间：栈和堆

## 1. 栈

本质上是函数运行临时用的小工作台，函数结束，台子直接清空

```c++
void someFunction()
{ 
	int x = 100; // x在栈上，4字节 
	double arr[10]; // 数组在栈上，80字节 
	// 函数结束时栈指针回退，x和arr自动”销毁”
}
```

栈的特点：

- **内存由操作系统自动管理**

  上述例子中定义局部变量，自动压入栈；函数执行完，自动回收内存。

- **栈空间很小**，一般就几MB（Windows默认1M，Linux默认8MB）

  栈开太大数组会直接栈溢出程序奔溃。

- 分配速度极快，只是移动指针，不需要找空闲内存块。

- 后进先出：最后放进去的变量最先销毁。

- 存放内容：**局部变量，函数参数，函数返回地址**

  注意不要返回局部变量的指针/引用，函数结束栈内存就失效，变成野指针。

- 大小在编译时确定，不支持**动态数组**

---

## 2. 堆

工作原理：相当于向系统租了一个大仓库，租和清理都需要你自己处理。堆内存是由程序员手动管理。`new`在堆上分配内存并返回**首地址**，`delete`释放这块内存。堆上的内存不会因为函数返回而自动消失—它会一直存在，知道程序显示调用`delete`或程序结束。

```c++
void func() {
    int* p = new int(10); // 在堆上申请一块int内存，p这个指针本身在栈上！
    int* arr = new int[1000]; // 堆上开数组
    
    delete p;      // 归还单个对象
    delete[] arr;  // 归还数组
  	arr = nullptr; // 置空，防止野指针
}

// p本身是局部变脸，但指向堆内存上的空间，函数结束，p被销毁，但堆内存上的空间未被销毁。
```

堆的特点：

- 程序员手动管理内存；
- 堆空间巨大；
- 分配慢，操作系统需要从堆中找到一块足够大的空闲内存块；
- 大小在运行时确定，支持**动态数组**；
- 自由使用，自行分配，自行释放；

---

## 3. 动态数组

动态数组等于在堆内存上开辟空间，大小在运行是确定；普通数组在栈上开辟空间，编译时就确定，大小必须写死。

```c++
void test()
{
    int n = 100;
    int* p_arr = new int[n]; 
    // p_arr 这个指针变量本身【在栈上】
    // new int[n] 在【堆】开辟能放n个int的连续内存，就是动态数组

    p_arr[0] = 1;
    p_arr[1] = 2;

    delete[] p_arr; // ！！！释放堆数组，必须带[]，和new[]配对
    p_arr = nullptr; // 置空，防止野指针(如果后续要接着使用该指针就置空)
}
```

> 注意：堆数组不能检查下标，超出范围，会破坏相邻堆内存。栈数组也有越界问题

```c++
int* p = new int[10];
// sizeof(p) 得到的是指针大小（8字节64位系统），不是数组总字节！
// 没法像栈数组那样 sizeof(arr)/sizeof(arr[0]) 求长度
```

> 因此现代C++提供了**容器**，不使用`new[]`

`std::vector`就是封装好的动态数组，底层依然是堆内存，管理`new[]`和`delete[]`，不用手动释放。

```c++
#include <vector>
void test()
{
    int n = 100;
    std::vector<int> vec(n); // 底层数据在堆；vec对象本身在栈
    vec[0] = 1;
    vec.push_back(99); // 自动扩容

    // 离开作用域，vec自动销毁，自动释放堆内存，无内存泄漏
}

```

优点：自动扩容；自动释放；自带`size()`获取长度，项目开发首选。
